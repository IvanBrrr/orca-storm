# Личный Telegram-бот

Каждая установка Orca подключает своего бота. Интеграция работает при запущенной
настольной Orca и доступном интернете. Для первой версии одна тема соответствует
одной встроенной сессии; переписка и управление поддерживаются для Codex.

## Подключение

1. Создать бота через [BotFather](https://t.me/BotFather).
2. Включить для него Threaded Mode. Telegram описывает этот режим в
   [Topics in Private Chats](https://core.telegram.org/bots/features#topics-in-private-chats).
3. Открыть Settings → Integrations → Telegram, вставить токен и подключить бота.
   Orca проверит токен и покажет имя и ID бота. ID заполняется автоматически:
   одного числового ID для авторизации недостаточно.
4. Нажать Link my Telegram account и открыть одноразовую ссылку. Она действует
   десять минут. После её открытия бот принимает сообщения только от связанного
   Telegram-аккаунта в личном чате.

Активные встроенные сессии появляются автоматически. Новые названия сессий
переносятся в темы. После закрытия сессии тема сохраняется, уведомления прекращаются.
Для другого агента тема показывает сведения о сессии; отправка задач пока доступна
только для Codex. Поддержка обычных терминальных CLI в эту версию не входит.

## Работа с телефона

- Сообщение в теме продолжает соответствующую сессию. При занятом агенте оно
  попадает в существующую очередь Orca.
- `/new` предлагает выбрать рабочую папку и создаёт сессию Codex с настройками
  запуска Orca. Новая вкладка появляется без переключения текущей вкладки пользователя.
- `/sessions` обновляет темы; `/status` показывает состояние текущей сессии;
  `/stop` передаёт запрос остановки её агенту.
- Вопросы и разрешения приходят с кнопками. Свободный ответ отправляется ответом
  на сообщение вопроса. Для нескольких вопросов бот собирает общий ответ.
- Фотографии и файлы прикрепляются к сессии. Голосовые распознаются моделью из
  настроек голоса Orca; перед отправкой расшифровку нужно подтвердить.
- Старые сообщения, полученные после запуска Orca, также требуют подтверждения.

Автоматические уведомления включаются при блокировке компьютера либо после трёх
минут бездействия. Если присутствие определить не удалось, уведомления разрешены.
Ответы на задачи, отправленные из Telegram, доставляются и при активном компьютере.
Этот режим сохраняется после перезапуска и учитывает сообщения в очереди.

Входящие файлы ограничены 20 МБ, голосовые — пятью минутами. Telegram хранит
неполученные обновления [не более 24 часов](https://core.telegram.org/bots/api#getting-updates).
Большой ответ отправляется файлом `answer.md` с предварительным просмотром в чате.
Документы и изображения из ответа пересылаются, если агент явно сослался на них
и они находятся внутри рабочей папки сессии. Ссылки наружу и выход через символьную
ссылку не дают боту читать другие файлы.

## Хранение и доставка

Токен защищается установленным системным `SecretStore`. В настройках он обратно
не выдаётся. Если шифрование недоступно, новый токен не сохраняется. Состояние
интеграции находится в `telegram-integration.json` в каталоге данных Orca; запись
использует `AtomicSnapshotWriter`, права файла — `0600` на поддерживаемых системах.

Связь темы и сессии, подтверждения, подготовленные вложения, позиция Telegram и
идентификаторы операций сохраняются на диск. Повтор обновления Telegram использует
тот же допустимый идентификатор операции в журнале Orca. Ответ на разрешение
проверяется по ID и ревизии вопроса существующим механизмом сессий.

Исходящие сообщения Telegram не поддерживают атомарную запись вместе с локальным
состоянием: при аварии между отправкой и сохранением отметки уведомление может
повториться. Это не приводит к повторному выполнению задачи агентом. При удалении
темы бот создаёт замену, сохраняя уже обработанные отметки доставки.

Интеграция обращается к существующему владельцу сессий и не создаёт отдельного
источника статусов. Файлы другой машины не читаются как локальные: загрузка вложений
через этот мост сейчас доступна только для сессий на локальном хосте без WSL.
Потеря связи с удалённым хостом не трактуется как завершение работы.

## Проверки

- `pnpm test src/main/telegram src/renderer/src/components/settings/TelegramIntegrationCard.test.tsx`
- `pnpm tc`
- `pnpm run check:code-quality:changed`
- `ORCA_BACKGROUND_LAUNCH=1 node tests/tools/telegram-settings-rendered/run.mjs`

Последняя проверка использует производственный компонент и CSS в скрытом Electron,
снимает состояния через CDP и декодирует синтетическое Ogg/Opus-аудио. Сетевые ответы
Telegram в проверках подменяются; подключение личного бота и качество распознавания
речи проверяются отдельно после ввода токена и настройки голосовой модели.
